# TS-035E3h: inert recorder controller

The accepted single-recorder smoke design is now implemented behind closed gates. The entry and controller constants remain false, the supervisor retains `CaptureRuntimeEnabled=false`, and the wrapper retains its unconditional design throw. No gate was removed. The compiled fixed root remains absent. No child process, recorder, compiler, Add-Type, benign executable, scriptc or linker ran during implementation or testing. The built recorder was read only as bytes for identity verification, never loaded, reflected over, interpreted as PE/CLR metadata or launched.

`runner.mjs` is the gated entry. Before any dynamic controller import, its future enabled path checks the embedded hash of `runtime-bindings.json` and verifies every bound file's ordinary ancestry, single-link identity, exact length and SHA with before/after filesystem checks. The manifest binds 20 inputs, including the accepted source, built binary and matching CLR config. A separate controller gate prevents bypass through direct import. `invocation.proposed.json` records the exact future Node executable, argument, cwd and 19-key environment, with authorization false. Future gate changes and execution require separate review.

`reused-identities.json` pins 18 byte-identical copies: the accepted proposals, exact oracle, supervisor/wrapper, status model, publication decoder, filesystem and alias guards, build identities and parent fragment. `parent.mjs` adds only necessary imports and an export around the exact inherited parent function. Its 90-second watchdog, stream handling and 10-second close wait are unchanged. Native alias verification uses the already enumerated named aliases and exact frozen counts/identities; no discovery or metadata subprocess is added. No library scan occurred.

The controller checks the full supplied environment and oracle, source/binary/config identity, named installed aliases, PowerShell/runtime/Roslyn and Node identities. It exclusively reserves the fixed root only after those checks. Five copies are staged with exact hashes, including the executable's matching `.exe.config`; the accepted source is verified without being copied or compiled. It checks every private input and requires an empty capture directory and no extra pre-launch file. Owned partial staging is retained. A callback records ownership immediately after exclusive reservation so later failure cannot erase or abandon the partial tree.

The future execution path dispatches the reviewed parent mechanism once. It validates parent transport and raw supervisor streams before parsing child status, then applies the accepted cleanup/status oracle and raw child-stream checks before collecting a publication snapshot. The precedence is transport, status/cleanup, bounded snapshot and staged-input identity, publication schema/duplicates/partial files, root PID, then exact raw/cwd/image/environment/API-argv UTF-16 fields. All gates must pass for `captured-attempt-count-unproven`; a marker is never treated as a complete capture certificate.

The supplied outer environment and observed child environment are separate checks. A correct parent environment cannot excuse different captured code units, and matching captured bytes cannot excuse changed launch arguments or environment. PID must match the supervisor root, all publication identities must agree, and creation time remains a nonzero runtime variable rather than the fixture's literal time. It is not independently authenticated. The result always retains `totalAttempts:null`, unproven coverage and no authority.

The actual `collect` function uses the reused bounded snapshot reader and output classifier, adding the accepted capture limits and filename/publication review. It does not traverse aliases or nested capture directories. Unknown files, extra inputs, missing publications, cap breaches, partial records and changed staged bytes are retained and refused. Status and four raw stream files are read with exact caps and filesystem checks; their hashes must match the captured tree. After review, source/tool/private-input identities and earlier output rows are checked again, followed by retained snapshot/result publication. Failure never triggers deletion, another dispatch or an alternate command. The future caller must retain outer invocation streams, including failures before root ownership.
