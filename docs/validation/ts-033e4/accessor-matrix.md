# Literal ER acceptance matrix (proposed; not executed)

Base b33fae6. R01–R28/R33–R34 belong to ER-A; R29–R32/R35 to ER-B;
R36 belongs only to separately authorized E4. Each ER row runs in both hosts.
Existing host control migration is additional preservation work, not a substitute.

Notation: U=guest undefined, D(v,w,e,c)=complete data descriptor,
A(g,s,e,c)=complete accessor descriptor, g/s=distinct callable object Values,
X=one preallocated ThrowCompletion with object payload, Y=one host Error sentinel.
All field projections must assert kind and absence of opposite-kind fields.
`[]` means no calls/ticks/effects, not an omitted assertion. Boolean results below
are normal completions unless explicitly abrupt. Use key `x` and separately a
GuestSymbol key; a second equal-description symbol must remain absent. For R01–28
generic host callbacks are legacy Realm builtins or explicit recording contexts,
never unguarded Script builtins. Receiver/Value equality means identity unless a
primitive expectation is specified.

E4 R36 includes execution design F04–F09 verbatim in scope: inherited restrictions,
computed names, descriptors and ordinary-object neighbors. It deliberately has no
invented whole-program tick count before E4 exists. ER R27/R28 have literal
bounded host counts now; E4 must add literal source ticks/frame assertions later.
Native hostile casts follow the already accepted E3A split only when the compiler
cannot represent them: retain exact compile-rejection diagnostics and separate
Node runtime negatives; never report compile rejection as native execution.
