From the repository root:

```powershell
node typescript/docs/validation/ts-032p/corpus.mjs
node typescript/docs/validation/ts-032p/check.mjs
git diff --check
```

Both Node commands exit0 under Node26.13.0. The default commands are read-only.
`corpus.mjs --freeze` was used once to retain the generated bytes; do not use it
as routine verification. `check.mjs --record` records the bounded design check
in `checks.json`; it does not regenerate literal vectors or accepted evidence.

## Literal expectations and new arithmetic check

`vectors.json` contains24 literal bit-pattern/radix/(s,n,k)/full-string expectations:
10 simple/boundary/contrast cases, seven retained interval failures, seven
cross-power Note2 cases. Exact binary strings, hex fractions and padding are
hand-derivable. Complex strings were frozen from the accepted exact oracle and
cross-checked against its retained research cases; they are useful regressions,
not a second mathematically independent oracle. No Number.toString output was
used as an expected value. `check.mjs` verifies the file; it never rewrites it.

`check.mjs` explores only the new unresolved cross-power selection calculation.
It reuses accepted free-format k, constructs half-gaps independently, and selects
at most six clipped floor/ceil candidates at three magnitudes. It compares with
the corrected oracle's exhaustive integer enumeration, without sharing its
decoder, midpoint addition or candidate search. The accepted free-format module
does import oracle bitsOf: consequently this experiment is not independent
evidence for initial decoding or for the proposed new iterative digit generator.

Measured:13350/13350 selector results match exact recommended (s,n,k), seven
changes from the old free-format choice, maximum retained k53,24/24 literal
expectations match. `checks.json` retains the result and explicit false flags
for production-backend/native-build execution. No broad engine survey or prior
native portability probe was rerun.

## Proof-review controls for the future implementation

These literal rational controls supplement the full-text vectors. They must
become assertions against the implementation's interval/selection helpers,
including synthetic helper inputs where actual shortest output would stop early.

|---|---|
| x=1, bits3ff0000000000000 | closed L=1−2^-54, H=1+2^-53; unequal margins |
| bits3ff0000000000001 | open endpoints at x±2^-53; midpoint equality rejected |
| bits0000000000000001 | open L=2^-1075,H=3·2^-1075; zero excluded |
| bits000fffffffffffff | odd/open; equal half-gaps2^-1075 |
| bits0010000000000000 | even/closed; equal half-gaps2^-1075 |
| bits0020000000000000 | even/closed; lower half-gap2^-1075, upper2^-1074 |

| synthetic q=1,x=7/2, allowed s3,4 at radix3,k2 | equal distances1/2; choose s4 (`11`), not s3 (`10`) |
| synthetic q=1,x=5/2, allowed s2,3 | choose even lower s2; reverse traversal does not change it |

These controls are specified, not executed against nonexistent production code.

## Source verification and limitations

Read the fixed ECMA-2622025 §6.1.6.1 Number-value rounding definition and
§6.1.6.1.20 steps5–6/Note2 through the web connector. Verified the artificial
2^1024 neighbor, binary even-significand tie rule, smallest k and distinction
between normative steps and the closest/even recommendation. See design links.

Read author-hosted Burger/Dybvig corrected PDF,9pages, DOI10.1145/231379.231397,
§§2.2–2.3/3.1 and Appendix A via extracted text. The text includes the correction
warning for the original correct-rounding theorem. The bibliographic publication
and corrected author URL are pinned; **a byte hash/revision date for this PDF
was not obtained**. Text extraction has corrupted math glyphs, so the design's
equations were independently derived and checked against the accepted local
research, not copied from extracted formulae. No paper/code content is vendored.

Source-access failures retained here as limitations: original Indiana and Tufts
URLs unavailable through web; author-PDF screenshots failed with cache miss;
local python launcher inaccessible; direct Node fetch of author PDF failed
ENOTFOUND. Successful web text access still verified the relevant prose and
correction. A reviewer wanting byte-level PDF provenance should obtain/hash the
corrected author copy; this is not claimed complete. No compiler/native failure
occurred because no compilation was attempted.

Resource bounds in the design are analytical, deliberately loose, and pending
independent review. The existing1081-bit/78-static-statement/167-case native
probe evidence remains inherited. This design adds no performance/memory,
cross-platform, full-interpreter lowering or exhaustive correctness result.
