# TS-031C-B return-only certification

Implementation base `802f595`, branch `codex/test262-classification`.
This implements the prospective return-only rule after accepted internal audit
`1bc8e11`. It does not admit a conformance profile or execute an upstream harness.

Ordinary parsing runs first. Only its unsupported `parse.return-context`
rejection requests `auditScriptReturns` on the identical source string. Complete
coverage with a nonempty candidate list changes only the rejection tag to
`syntax-error/return-outside-function`. A blocked audit preserves the original
first error, including its message, location and partial body. Source and parser
depth guards retain their counts and priority. No new grammar, ASI or strict
execution behavior is added.

Observation projection now exposes parse phase, SyntaxError constructorName and
the return rule without creating or reading a guest Error object. Explicit JSON
serialization carries those fields. The closed child decoder accepts only this
one rule and the existing operation validator requires test stage, a location,
and bodyEvaluated false in either observation mode. Parent composition uses the
existing bound context and still records no loaded harness, no harness validation
and no classification. The other four reserved syntax rules remain non-emitting.

## Assertion and source preservation

[Before-edit inventory](assertion-inventory.md) records each intentionally updated
old assertion. All original cases and unrelated expectations remain. Historical
audits and evidence are unchanged. `run.mjs` compiles the four parser modules
from base 802f595 and compares complete ParseResults against the new build,
allowing only the tag delta determined by the frozen literal coverage matrix.
It compares before/after internal audit results and checks exact native/Node
audit text, rejected-source observations in both modes, and unchanged CLI
diagnostics/exits. It never derives eligibility from the implementation under
test, expected-negative metadata, a message or test identity.

The matrix reuses unchanged TS-031C-A F01-F29/X01-X09 literals and TS-031C-P
C01-C07 controls. Five pinned S18-S22 blobs are Git-SHA-1 verified and all eight
variants preserve exact source bytes and the existing strict prefix. F25/C08
additionally run through real parent/child transport with null, parse/SyntaxError
and runtime/TypeError metadata, in both modes and lanes. All observations remain
separate from conformance. The internal driver checks unchanged Realm bindings,
binding identity/payload and output after audit and rejected-source observation,
with zero step/call budgets. X07's assignment/output cannot execute.

The existing protocol operation matrix now includes certified returns; an
additive control tests both modes, all four other reserved codes, unknown/missing
fields, runtime phase, wrong constructor, forged coverage/capability fields,
body/stage/location contradictions, stale nonce, changed unit/mode and injected
source identity. Existing framing, context, transport and ledger controls remain.

`preservation.mjs` checks all 212 complete old guest records in each lane, all
36 original gate identities and independent static coverage verdicts, plus
unchanged engine/test/tool/config/fixture files outside the eight enumerated
implementation/test paths. Build registration and compiler pins are untouched.

installation); `native-build-failed.json` retains complete subprocess results.
`host.log` retains three temporary-ledger EPERM rename failures; the unchanged
host controls pass in `host-approved.log`. These are environment failures, not
skips or relaxed compiler/test gates.

The initial concurrent `observations.log` has 14/16 controls passing. T31 hit
sandbox EPERM for its junction. T30 returned unfinished but had no transport.json;
its complete available archive is retained in `cancellation-attempt/`. The
unchanged launch code awaits validateLaunch before checking an already-aborted
signal and then returns without creating transport.json. Thus the existing

the running-child path it assumes. This is an existing test timing limitation,
not a certified-return discrepancy. The standalone access-enabled rerun in
`observations-approved.log` passes 16/16 without changing an assertion, timeout,
transport code or cancellation behavior. Follow-up ownership belongs to the
coordinator; this slice does not expand into transport lifecycle changes.

No compiler/runtime discrepancy, compiler workaround, oracle weakening or
source-location correction was needed. Log trailing whitespace is normalized;
the retained subprocess JSON preserves original strings.
