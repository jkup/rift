# Exact cmd OS identity amendment: design only

This proposal implements only the root-authorized two-name cmd identity policy. e37d049's original single-link failure, audits, rejected runner and all older evidence remain immutable. No amended run(), scriptc, C# compilation, benign/diagnostic fixture or lifecycle repeat is authorized or performed.

The accepted names are exactly the existing contract's `C:\WINDOWS\system32\cmd.exe` and the recorded `C:\Windows\WinSxS\amd64_microsoft-windows-commandprompt_31bf3856ad364e35_10.0.26100.9549_none_26c71961ca689840\cmd.exe`. Each must be an ordinary regular file with canonical ordinary ancestry, no symbolic link or Windows reparse attribute, device1045235170, file identity562949954062573, exactly2 links,339968bytes and SHA-25615cd209c995b7d3009c91ca40892d5b8f1fb162f3e5f10716642ea278e8e0d7b. Both names are independently read and hashed. Identity/size/link count are checked across each read. Fixed names, exact recorded identity and linkcount2 reject substitution, an extra name, or removal of either expected name.

`cmd-identity.mjs` is a narrow shared reader/validator for preflight and runner. Node lstat and canonical-path checks are supplemented by Windows GetFileAttributesW for every ancestor, including volume root and the final file, because lstat does not expose every reparse attribute. The checker rejects FILE_ATTRIBUTE_REPARSE_POINT even when Node reports a regular file. It uses the pinned runtime's built-in `node:ffi` lazily, calling only DWORD GetFileAttributesW(LPCWSTR) from the fixed installed system kernel32.dll, with a live null-terminated UTF-16LE Buffer. There is no native addon, Add-Type, external metadata child, installation or environment edit. The library is closed; load/query/close failures are retained and cannot become a successful identity. INVALID_FILE_ATTRIBUTES is recorded as query failure; no unmeasured GetLastError value is invented. This new experimental FFI dependency and its availability warning are explicit in ffi-audit.json, not silently suppressed. See [Node FFI](https://nodejs.org/api/ffi.html) and [GetFileAttributesW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileattributesw). Root must review this exact native read-only dependency with the amendment.

The reader returns both records and original read errors. Validation requires an empty error list and the complete expected records; it provides no fallback. A rejected ancestry is never used to hash cmd bytes. Native read-only inspection is permitted by this design task, but no compiler observation is. The module's pure validator does not load a DLL during inert tests.

Preflight uses the shared check and returns both cmd records. Node, PowerShell and Zig still go through unchanged generic single-link/canonical-path/hash checks. The runner writes cmd-before.json **before** validation, then validates the same policy before any supervisor spawn. Its finally collection writes cmd-after.json before validation and requires complete snapshot equality to cmd-before, including both identities and all ancestry attributes. These records are separate from tools-before/tools-after, which retain the other three tools with their original identity function. Partial records and read errors remain on failure; a successful post-check cannot erase a failed pre-check. This separation is cmd-only, not a generic alias exemption.

Generic exact(), identity(), directory-tree/project/package/copy checks, all other tools' single-link requirements, the supervisor controller and status validators are byte-identical to e37d049. The full wrapper, accepted noninstrumented supervisor, contract, command, four pins,21-key environment, inventories, sidecar exclusion, source bytes and limits are unchanged. The runner's only functional amendments are the shared import, relocated historical-input path, cmd-before capture/validation, and cmd-after capture/validation/no-drift check. Complete source transformations and hashes are frozen. No cmd path/hash/environment value changes.

The independent full positive literal uses fixed identities/size/hash from root review and a separate read-only .NET GetAttributes inspection of all9 ancestry entries. It is not generated by the new FFI reader. Inert controls reject70 altered records plus two wrong contract arguments, including different/missing/extra names, extra link, mismatched device/file identity/hash/size, native reparse flags, redirected ancestors, symbolic links and wrong kinds. Source guards also compare whole unchanged generic and controller/status sections. Existing63status/two-stream/three-wrapper tests are preserved, not repeated. Syntax checks do not compile C#.

Read-only preflight evidence, if obtained, belongs to this amendment only; it does not turn the old failed preflight into a pass. Any new issue stops and returns for review without another attempt or alternate mechanism. All existing seals, original failures,163+205+108+71 archives and four output trees remain preserved.

The identity check trusts the installed OS and pinned Node/FFI implementation. kernel32.dll remains an explicit cooperative OS dependency, not a newly certified transitive DLL closure. Before/after observations cannot prevent or detect every transient mutation, hidden read or external write. No hermeticity, build certification, receipt, registry, E3e/E3c/E2 authority or execution permission is inferred. Return to actual+second review before any amended run() invocation.
