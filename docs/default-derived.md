# Default derived class constructors

TS-158 admits class heritage when the derived class has no explicit constructor. Heritage is evaluated in the strict class scope while the inner class name is still uninitialized. The class constructor inherits from its superclass, and its instance prototype inherits from superclass.prototype; null heritage gives a null instance-prototype parent. Invalid superclass values or prototype values throw guest TypeErrors before computed method names run.

Default derived construction reads the constructor's current prototype, verifies that it is constructable, and forwards the existing argument list with the original newTarget. It performs no eager receiver allocation and does not consult Array.prototype's iterator. This supports dynamic constructor-parent replacement and existing builtin internal storage through the TS-157 construction path. Calls without new retain the class's defining-Realm TypeError behavior. No synthetic constructor source or argument array is created.

Explicit derived constructors, super calls/properties, fields, private elements and static blocks remain unsupported. A computed method named constructor is an ordinary method and does not count as an explicit constructor. Legacy parsing retains its boundary. This is not complete class inheritance support; derived this binding and method home objects remain separate increments.
