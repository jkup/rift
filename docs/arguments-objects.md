# Arguments objects

TS-144 is accepted.

The first slice adds GuestArguments storage backed by parameter binding cells. Ordinary descriptor storage remains responsible for validation and attributes; mapped reads substitute the current cell value. Successful value definitions update the cell. Deletion, accessor conversion and making an index non-writable disconnect its mapping. A non-writable definition without a value snapshots the current parameter before disconnecting. Failed definitions and failed deletion retain the mapping. Writes through another receiver leave the parameter unchanged.

The focused storage driver exercises these rules through Rift property operations, including inherited receivers, detached descriptors, seal/freeze and index writes that do not change length. Bounded allocation uses the defining Realm's Object prototype and captured original Array values iterator and restricted-function thrower. Mapped objects receive the supplied callee; unmapped objects receive non-configurable throwing callee accessors. Both have the Arguments builtin tag.

Function activation creates the implicit binding before initializing parameters. Sloppy simple parameters share their existing binding cells; strict, rest and default parameters use unmapped objects. Arrows inherit the enclosing binding. Explicit parameters named arguments suppress the implicit object; without initializers, body function and lexical declarations named arguments also suppress it. The private execution handoff carries the actual called object, including host shells, so callee identity does not depend on a canonical materialized function. Public setup rejects functions requiring arguments before consuming activation or budget.

The declaration traversal records arguments identifier uses in their nearest ordinary function, crossing arrow and block scopes. Functions without such uses omit allocation. This is sound within the current boundary: eval and with remain unsupported, and Function construction uses global scope. Shadowed uses can conservatively request an unused object; no analysis removes an observable binding. Strict binding names and assignments are rejected before execution, including parameter defaults and nested functions, without expanding certified syntax-rule allowlists. Existing functions without arguments uses retain their allocation and budget path.

References consulted 2026-11-09: ECMAScript [arguments exotic objects](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-arguments-exotic-objects) and engine262 [arguments operations](https://github.com/engine262/engine262/blob/main/src/abstract-ops/arguments-operations.mts). Rift uses direct binding cells instead of hidden getter/setter functions per mapped index; these cells stay inside host implementation state. Mapping semantics follow the descriptor algorithms, including taking a value snapshot before removing a writable mapping.
