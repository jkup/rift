# Array fill and copyWithin

Both methods capture the array-like length before coercing indices, mutate the receiver in place and return that same boxed object. They never set length explicitly or consult constructors/species. Fill performs throwing writes in ascending index order. CopyWithin selects the overlap-safe direction, then reuses the existing property move operation: HasProperty, Get and throwing Set for present values, or throwing deletion for holes. Inherited values and setters therefore remain observable, and a later failure leaves earlier changes intact.

The implementation follows [ECMAScript 2025 fill](https://262.ecma-international.org/16.0/#sec-array.prototype.fill) and [copyWithin](https://262.ecma-international.org/16.0/#sec-array.prototype.copywithin), reviewed against [engine262 ArrayPrototype at 18cdeb03](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/intrinsics/ArrayPrototype.mts). Each iteration consumes the operation budget. Tests cover overlap in both directions, holes, inherited properties, accessor order, coercion-driven mutation, frozen/read-only properties, partial failure, generic receivers, metadata and huge array-like lengths.
