# Bounded RegExp matching

The standalone matcher compiles the admitted non-Unicode pattern AST into regex instructions and executes them with an explicit backtracking stack. This is confined to regular expressions; JavaScript execution remains tree walking. No pattern or guest source is passed to host RegExp or another interpreter.

Ordered split instructions preserve left-to-right alternatives and greedy/lazy repetition. Each pending alternative owns its capture and progress snapshots. Repetition clears all captures inside its atom before an iteration; abandoning that iteration restores the previous snapshot. Optional iterations that consume no input fail, while required empty iterations can satisfy a minimum. These rules preserve both termination and the final iteration's captures.

Positions and capture ranges are UTF-16 code-unit offsets. Captures use paired start/end slots, including group zero; an unmatched capture has two -1 slots. The search operation accepts an already validated nonnegative integer start offset and a sticky choice. Anchors, ASCII word boundaries, dotAll, multiline and non-Unicode ignoreCase are supported. Case-insensitive classes canonicalize their actual range members, not merely the range endpoints. Canonicalization uses the existing string uppercase boundary and preserves the non-ASCII-to-ASCII exclusion.

Compilation, range expansion, state initialization, transitions, capture clearing and snapshot copying charge the supplied operation context. Large finite repetitions can exhaust that budget during compilation. Matching uses no recursive host calls, and exponential backtracking exhausts the budget with an explicit resource completion. This is bounded execution, not a linear-time algorithm. Compilation follows the parser's maximum 128 nested groups. Match state is per invocation, so programs retain no previous result or budget.

This slice does not expose guest objects, literals, lastIndex or symbol protocols. Backreferences, lookaround, named groups and Unicode modes remain outside the parser's admitted subset.

Semantics follow ECMAScript 2025 [RepeatMatcher](https://262.ecma-international.org/16.0/#sec-runtime-semantics-repeatmatcher-abstract-operation) and [Canonicalize](https://262.ecma-international.org/16.0/#sec-runtime-semantics-canonicalize-ch). V8's [RegExp architecture discussion](https://v8.dev/blog/non-backtracking-regexp) informed the explicit instruction/stack design; this implementation does not adopt its alternative linear-time algorithm. The rejected host-backend evidence is recorded under [TS-168](validation/ts-168/README.md).
