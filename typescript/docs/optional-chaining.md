# Optional chaining

TS-148 adds optional named/computed access and calls to structural Script parsing. A chain stores its base and ordered member/call links. Optional links test only null and undefined, before evaluating their keys or arguments. Ordinary links after the first optional link belong to the same chain. Parentheses end that chain; a following optional link starts another one. The lexer excludes a decimal digit after `?.`, preserving conditional expressions such as `true?.3:0`.

Private expression evaluation can return a value, a property/binding reference, or an abrupt completion. A chain preserves its final reference so grouped calls retain their receiver and delete does not invoke a final getter. Intermediate references are read once before proceeding. Existing property helpers retain their established key conversion and primitive receiver behavior. Chain links consume the shared step budget; calls and subexpressions keep existing resource guards. Function metadata and declaration traversal include keys and arguments even when runtime evaluation will skip them.

Assignment and update targets cannot be chain nodes. Ordinary members after grouping remain assignable. Unparenthesized optional constructor operands, tagged templates, super/private members and eval remain unsupported. Legacy parsing still rejects optional chaining. No syntax-certification allowlist was expanded.

References consulted 2026-11-09: ECMAScript [optional-chain evaluation](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-optional-chaining-evaluation) and [ChainEvaluation](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-optional-chaining-chain-evaluation), and engine262 [OptionalExpression.mts at 18cdeb03](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/runtime-semantics/OptionalExpression.mts). The implementation uses a flat link list and explicit completions rather than recursive generator evaluation.
