# Shared destructuring design

Design for TS-152. Pattern syntax and execution are not admitted yet; the IteratorStep prerequisite is tracked below. Targets are the unchanged destructuring, for-destructuring and comma-operator fixtures. Generator fixtures still require a separate subsystem.

Patterns need their own representation. Array/object literal evaluation must not run when the syntax represents a binding or assignment pattern. Keep original binding sites, defaults, rest positions, computed property expressions and nested patterns available to both the declaration collector and evaluator. Assignment leaves may be references; binding leaves must be identifiers. Reject invalid rest placement, optional-chain targets, methods/accessors and compound assignment patterns without widening syntax certification.

Declaration planning must enumerate every bound name before execution, while traversing all default/key expressions for nested functions, strict restrictions and arguments/eval use. Lexical bindings exist in TDZ before the initializer runs. Each binding initializes in source order, so earlier bindings are visible to later defaults and later bindings still throw. Var and assignment leaves use PutValue; let/const use initialization. Loop patterns need fresh lexical environments per iteration and the existing iterable-expression TDZ environment.

Array patterns use the iterator protocol, including empty patterns. Elisions advance with IteratorStep and never read the result's value getter. Rift currently exposes only iteratorStepValue; extracting the step operation is the first small prerequisite. Keep its existing tick, done-state and abrupt behavior. An exhausted iterator supplies undefined for later elements without further next calls. Defaults run only for undefined. Rest consumes the remaining iterator into a fresh Realm array. Close an unfinished iterator on early normal completion or a guest abrupt completion, preserving original throw precedence; engine limits and host faults must not resume guest cleanup. Nested patterns close the appropriate inner and outer iterators in order.

Do not collect values before assigning. A leaf's reference is evaluated at its specified point before reading the corresponding iterator element or object property; nested patterns do not evaluate their leaves until their input is available. Defaults can mutate bindings and objects, so retain the actual reference rather than resolving its name again afterward. Preserve anonymous function name inference for identifier defaults.

Object patterns require coercible input even when empty. Computed keys evaluate and convert once, in order; ordinary property reads may see inherited properties. Rest snapshots own keys, excludes already selected string and symbol keys, checks enumerability at copy time, reads each remaining value, then creates own data properties on a fresh object. Object.assign's Set behavior is unsuitable because it may invoke setters. `__proto__` is an ordinary pattern key, not object-literal prototype syntax.

Validation needs observable next/done/value/return order, throwing getters, elisions, exhaustion, defaults, nested close precedence, exact abrupt identity, TDZ and const errors, cross-Realm allocations, closure capture, computed/rest key effects, resource bounds and original source spans. Pattern recursion must share evaluator depth with calls and defaults; parser depth alone does not bound reentrant execution. Existing declaration/assignment/loop audits must remain closed when they encounter unsupported patterns.

References reviewed: ECMAScript 2025 [destructuring assignment](https://262.ecma-international.org/16.0/#sec-destructuring-assignment) and [IteratorBindingInitialization](https://262.ecma-international.org/16.0/#sec-runtime-semantics-iteratorbindinginitialization); engine262 [DestructuringAssignmentEvaluation](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/runtime-semantics/DestructuringAssignmentEvaluation.mts) and [IteratorBindingInitialization](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/runtime-semantics/IteratorBindingInitialization.mts).

## IteratorStep prerequisite

IteratorStep now returns the original iterator-result object or an internal null exhaustion marker without reading value. iteratorStepValue delegates to it, then performs the value read and preserves its prior abrupt/done behavior. The same single tick remains before next. Callers still decide whether a done record should be advanced. This follows ECMAScript 2025 [IteratorStep](https://262.ecma-international.org/16.0/#sec-iteratorstep) and [IteratorStepValue](https://262.ecma-international.org/16.0/#sec-iteratorstepvalue).

Reference-order review: ECMAScript 2025 [EvaluatePropertyAccessWithExpressionKey](https://262.ecma-international.org/16.0/#sec-evaluate-property-access-with-expression-key) deliberately retains the unconverted property-name value in a reference. For assignment, ToPropertyKey occurs later during PutValue, after RHS evaluation. Rift already follows this ordering. Pattern assignment must evaluate the target reference before fetching its element/property without prematurely converting an object-valued target key. This differs from computed object-pattern selection keys, which convert before reading the selected source property. Include a mutation-sensitive key test to prevent accidental early conversion.

C++ reference review: src/interpreter/statement_evaluator.cpp has separate array declaration and assignment iterator loops. Both look up next repeatedly and can turn a non-callable next or non-object result into exhaustion. Those are not semantics to preserve in the rewrite. Keep the shared GetIterator/IteratorStep operations, cached next method and TypeError behavior; preserve the C++ source and fixtures as reference evidence.

## Object binding declarations

ObjectPattern now records property-key expressions, shared pattern elements and an optional identifier rest binding. The direct binding parser admits shorthand, aliases, computed/literal keys, nested arrays/objects and defaults without changing object literal or assignment cover grammar. Declaration traversal visits computed keys and defaults in source order. Array and object patterns share reference capture, default evaluation, inferred naming and final binding initialization.

Object execution rejects null/undefined before evaluating keys, converts each selected key once, resolves var references before property reads, and preserves the original primitive receiver for selected GetV reads. Rest snapshots own keys after selected properties finish, excludes string/symbol keys using identity/value equality, rechecks enumerability, reads each remaining value and defines fresh data properties. It neither copies inherited properties nor invokes destination setters. Allocations/errors belong to the defining Realm; nested execution shares depth and step budgets.

## For-in/of binding patterns

Iterable evaluation sees the complete mutable TDZ environment; each iteration gets a fresh environment with the declared mutability before shared pattern initialization runs. var patterns use the existing variable scope and ordinary binding writes. Computed keys/default functions participate in declaration traversal under the appropriate loop scope. Existing single-name and classic-for setup paths retain their observable budgets.

Pattern initialization errors flow through the same outer iterator-close path as body errors, after any nested pattern cleanup. The active frame is restored before closing the outer iterator. Fatal limits and host faults retain their existing bypass rules. Classic-for patterns and assignment-pattern heads remain unsupported in this slice.
