# new.target in Script functions

TS-153 now admits new.target in ordinary function parameters and bodies, including class and object methods. Calls expose undefined; construction exposes the actual constructor. Arrows retain the surrounding ordinary function environment, including escaped closures. Bound construction uses the underlying constructor. Direct eval inherits whether a function context exists, even when its new.target value is undefined; indirect eval and Function-created code do not inherit the caller's context.

The parser carries that context through every rejection-only preparation retry. Function activations store the target explicitly; evaluation walks past declarative and arrow environments to the nearest ordinary function. No guest source is rewritten and no Realm-global target state is introduced. Class computed names use the enclosing context; method bodies establish their own function context. Original source text remains available to Function.prototype.toString.

This increment retains explicit unsupported rejection for new.target outside a function and for the legacy parser. It does not add a certified outside-function early error, nested unparenthesized new operands, Reflect.construct, distinct newTarget forwarding through builtins, derived classes or super. Those construction changes need separate review before admitting inheritance.

The historical harness-construct source function C(){new.target;} is preserved and migrated to inert preparation plus successful ordinary call and construction checks. Focused tests cover defaults, nested/escaped arrows, bound constructors, methods, computed class names, direct/nested/indirect eval, Function, cross-Realm identity, the four rejection-only retries and invalid contexts. Full canonical acceptance remains pending.

Reviewed references: [ECMAScript 2025 GetNewTarget](https://262.ecma-international.org/16.0/#sec-getnewtarget), [new.target evaluation](https://262.ecma-international.org/16.0/#sec-meta-properties-runtime-semantics-evaluation), [PerformEval](https://262.ecma-international.org/16.0/#sec-performeval), and engine262 [NewTarget.mts](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/runtime-semantics/NewTarget.mts) and [PerformEval.mts](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/abstract-ops/global-object.mts), pinned to 18cdeb03c363eb31d775648a0d070bdc8a26ced1. The runtime follows GetThisEnvironment's exclusion of lexical-this functions, without sharing the reference engine's representation.
