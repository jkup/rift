# Method home objects and super properties

TS-160 adds super property references for class and object methods, accessors and constructors. Fields, private elements and Proxy remain unsupported.

Callable metadata retains the method's home object. Class instance methods and constructors use the instance prototype; static methods use the constructor; object methods use their literal object. Moving or binding a method preserves that home. Property lookup reads the home's current prototype, while the receiver remains the current this binding. These are deliberately separate: inherited getters, setters and method calls act on the current instance.

A Script super-reference wrapper carries that receiver alongside the existing mutable Reference and strictness. GetValue and PutValue accept an explicit receiver while retaining the original default for ordinary references. Successful key conversion stays cached on the same Reference across compound assignments and updates; no new property-operation implementation or shared record shape is needed. Deleting a super reference throws ReferenceError before key conversion.

Evaluation reads this before a computed key expression. It then captures the lookup base, but leaves key coercion to GetValue or PutValue. A simple assignment evaluates its right side before converting the key, while a compound assignment converts once before its Get. Mutating the home prototype during the key expression affects lookup; mutating it later during the right side does not change the captured base. A null base fails before key coercion.

Parser context distinguishes ordinary code, methods and derived constructors. Methods admit properties; derived constructors additionally admit calls. Arrows inherit context, ordinary functions reset it, and direct eval inherits the nearest nonlexical function's home metadata. Rejection-only audits retain the same context. Super references work as call receivers, update targets, destructuring targets and for-in/of assignment targets.

Reviewed against ECMAScript 2025 [super evaluation](https://262.ecma-international.org/16.0/#sec-super-keyword), [Reference Records](https://262.ecma-international.org/16.0/#sec-reference-record-specification-type) and [MakeMethod](https://262.ecma-international.org/16.0/#sec-makemethod), and engine262 `18cdeb03c363eb31d775648a0d070bdc8a26ced1` (`src/runtime-semantics/SuperProperty.mts`, `src/execution-context/Environment.mts`). Rift retains explicit completions and its existing property operations.

Canonical validation is pending. Focused tests cover home identity, prototype mutation, inherited accessors, strict/sloppy writes, key order and cache, deletion, null bases, arrows/eval, distinct receivers, cross-Realm errors and fatal limits. Historical method/class boundary tests preserve their original strings with explicit admission checks. The unchanged class-test.js and test-class-getter-setter.js are exercised on both hosts with hashes and full process output retained.
