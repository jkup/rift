# Locale string conversion

TS-146 implements Object, Array and Number toLocaleString for the Script profile. Rift does not implement ECMA-402 Intl. Its documented ECMA-262 fallback uses ordinary decimal Number formatting and a comma list separator; reserved locale/options arguments are ignored, including when invoking element methods.

Object.prototype.toLocaleString invokes the receiver's current toString with no arguments and returns its result unchanged. The Invoke helper boxes only for property lookup: accessors and calls receive the original primitive or object. Number.prototype.toLocaleString checks the Number slot and formats it directly, without consulting a mutable public toString property.

Array.prototype.toLocaleString captures length before traversal, reads every index (including inherited properties), leaves null and undefined elements empty, invokes each other element's current method, then converts that result to a string. It shares JoinIndexedProperties with join; join retains its original tick and conversion order. Getter, call and conversion failures preserve completion identity. Large traversals and recursive guest calls use the existing resource guards.

References consulted 2026-11-09: ECMAScript [Object.prototype.toLocaleString](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-object.prototype.tolocalestring), [Array.prototype.toLocaleString](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.tolocalestring), [JoinIndexedProperties](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-joinindexedproperties), and [Number.prototype.toLocaleString](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.prototype.tolocalestring). engine262's [ArrayPrototype.mts](https://github.com/engine262/engine262/blob/main/src/intrinsics/ArrayPrototype.mts) likewise uses the shared joining operation, a comma separator and no element arguments without Intl.
