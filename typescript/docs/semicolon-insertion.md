# Script automatic semicolon insertion

TS-149 accepts implicit statement terminators at end of input, before a closing brace, and across an intervening line terminator once the current statement production is complete. It does not rewrite source or insert tokens. Both classic-for header separators remain explicit. Existing do-while handling already admits its optional final semicolon.

The expression parser continues calls, members, optional chains, binary/conditional expressions and comma expressions across line breaks. A line break before postfix update instead ends that expression, so the update token belongs to the next statement. Return omits its expression across a line break or before a closing brace/end of input. Break/continue still read labels only on the same line. Throw keeps its no-line-terminator restriction and requires an expression. Empty statement bodies are never synthesized.

A shared token-gap scan examines source between the previous token's end and the next token's start. Token start-line comparison alone is insufficient because string continuations and templates can span lines internally. Directive analysis uses that same scan and checks whether the next token continues the string expression. An implicitly terminated raw use-strict string therefore establishes strictness, while a string followed by a call, member, operator or other expression continuation does not. Raw spelling, statement ends and function source text remain intact. Legacy parsing retains explicit semicolons.

References consulted 2026-11-09: ECMAScript [semicolon insertion rules](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-rules-of-automatic-semicolon-insertion) and engine262 [StatementParser.mts at 18cdeb03](https://github.com/engine262/engine262/blob/18cdeb03c363eb31d775648a0d070bdc8a26ced1/src/parser/StatementParser.mts), especially eatSemicolonWithASI.
