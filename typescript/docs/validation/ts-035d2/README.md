## Implementation

The exact eight production files implement the accepted
[dispatch design](../../script-strict-rule-dispatch.md). Fresh bounded preparation
uses the same EOF parser and a single collector traversal. The collector returns
its ordinary result unchanged unless its global audit certifies strict ordinary
block function duplicates; the selected diagnostic is the earliest second site.
No partial body or detached public audit supplies preparation authority.

C projects that block rejection before the byte-equivalent independent legacy
return fallback. Return certification remains parse-only/test. X06 in both source
orders stays unsupported. Ordinary planners, strict preparation, D1, v1, language
grammar, registry, corpus admission and compiler pins are unchanged. The v2
serializer writes the actual closed rule code; both decoder allowlists add only
the block code.

From `typescript/`, with the pinned Zig directory on PATH:

```text

```

static-only/separate coverage gates, the frozen 90-source matrix in each host with both runtime fixtures (360 runs),

retries only evidence-write `UNKNOWN/open` failures, bounded to 20 attempts with
50ms waits. It changes no interpreter, assertions or process outcome rules.

I/O failures are not semantic assertions.
