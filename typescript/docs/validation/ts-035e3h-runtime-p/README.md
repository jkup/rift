# TS-035E3h runtime-P: first recorder runtime prerequisite

Choose a single direct recorder smoke contract as the next implementable prerequisite. Do not add an offline PE/CLR parser first. Accepted build evidence already fixes the output bytes and the intended x64 Framework build. Metadata could describe headers, CLR declarations and an entry-point token; it cannot show that this file starts under the installed CLR, calls the Windows APIs successfully, preserves UTF-16, publishes files in the intended order, or holds until job termination. Nor would metadata establish source-to-binary equivalence. Runtime evidence is required for those gates. This design does not parse or load the binary.

The [Microsoft PE specification](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) describes image structure; it does not certify program behavior. [CommandLineToArgvW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-commandlinetoargvw) documents a specific quoting interpretation, so the API argv view stays distinct from the received raw command line. [TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject) terminates associated processes with the supplied exit code; a forced code is therefore the intended observation after the marker stop, not a successful natural program exit. These official pages were read for design; no runtime API was invoked.

The first scope is one future recorder launch, directly through the bounded job supervisor, with one future supervisor Add-Type bootstrap and no helper recompilation. No producer, compiler driver, linker, response-file access, concurrent second launch, injected filesystem fault or alternate command belongs in that run. The expected result is a complete single registered capture with **totalAttempts:null**, consistent with a hold until termination. This neither establishes a complete attempt census nor proves race/fault handling. All implementation and execution authority remains false.
