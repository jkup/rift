# Synchronous for-in

TS-127 supports one identifier let/const/var head or an existing identifier/member assignment target. It reuses for-of's lexical RHS TDZ, fresh lexical bindings, declaration conflict checks and body completion handling. For-in skips null and undefined, boxes other primitives, and enumerates string property names. It never reads Symbol.iterator, property values or an iterator return method.

`ForInEnumerator` implements the ordinary-object enumeration algorithm directly. It snapshots ordered own keys separately for each prototype, checks the current descriptor before yielding a key, and records existing names even when non-enumerable so they shadow inherited names. Deleted names are not marked visited. Symbol keys are ignored. The array cursor avoids shifting queues; a Set avoids scanning the visited-name list for every key. Prototype and key scans charge the session budget, including objects with no enumerable keys. As with Object.keys, the underlying ordinary own-key snapshot is a host allocation before the individual scan ticks.

Deletion and enumerability changes are observed when a candidate is visited. Keys added after that object's snapshot are not visited. Each next prototype is read after the current object's keys are exhausted. ECMAScript allows implementation differences under some mutations; these choices follow its reference For-In Iterator algorithm. Proxies and other unimplemented exotic objects are not introduced here.

References consulted on 2026-11-09: [For-In Iterator objects](https://tc39.es/ecma262/multipage/ecmascript-language-statements-and-declarations.html#sec-for-in-iterator-objects), [EnumerateObjectProperties](https://tc39.es/ecma262/multipage/ecmascript-language-statements-and-declarations.html#sec-enumerate-object-properties), and V8's [runtime-forin.cc](https://github.com/v8/v8/blob/main/src/runtime/runtime-forin.cc). V8's cache and accumulator optimizations were not adopted; direct traversal fits this interpreter and preserves the specified duplicate/descriptor behavior.

Destructuring, multiple bindings, labels, async loops and Annex B var-head initializers remain excluded. Legacy parsing is unchanged. Existing rejection sources now have explicit current expectations; the frozen audits and production Test262 admission remain unchanged.
