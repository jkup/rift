# Sloppy block functions

TS-145 is accepted. It adds unique function declarations in sloppy blocks and switch bodies. Each declaration retains its block lexical binding. Eligible declarations also create an outer var binding during instantiation and copy the block function into that binding only when execution reaches the declaration. Skipped branches and early abrupt completion leave the outer binding unchanged.

Declaration planning records eligible declaration IDs separately from syntactic VarDeclaredNames. Parameters and intervening lexical declarations veto the outer binding; catch parameters and other sloppy block functions do not. Existing global lexical declarations and failed CanDeclareGlobalVar checks suppress the global extension. Global eligibility belongs to the active evaluation, not the reusable source record. Function bodies write directly to their variable environment, so an intervening catch or block binding cannot redirect the assignment.

Arguments needs special treatment. Ordinary functions retain an observable implicit arguments binding even when the only use is a synthetic block-function write. A separate body variable environment, or an arrow, creates a missing arguments binding when the declaration executes. It must not shadow inherited arguments before that point. Strict blocks retain lexical-only behavior. Duplicate sloppy block functions, labelled functions, bare if-arm function declarations and eval remain unsupported.
