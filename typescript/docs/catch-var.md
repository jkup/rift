# Simple catch parameters and var declarations

TS-155 admits a var declaration with the same name as a simple catch parameter. The Annex B.3.4 replacement early error applies in strict as well as non-strict source. The handler still rejects an immediately nested lexical declaration with the parameter's name. Destructured catch parameters remain unsupported, and the legacy declaration planner keeps its boundary.

Rift already hoists handler var declarations through the catch scope and resolves var initializers against the active lexical environment. Consequently, the outer var binding is created but the initializer writes the catch parameter. Existing array/object var patterns, classic-for initializers and for-in/of heads use the same resolution and are covered explicitly. Nested catches and closures retain the appropriate binding. Existing eval preparation skips CatchActivation while checking var conflicts; direct eval var and function declarations, strict eval isolation and the separate block-function rule are retained.

The change removes only the bounded collector's simple catch-var veto in its ordinary projection and whole-source audit. No new environment type or runtime path is needed. Tests retain lexical conflicts, outer lexical-var conflicts, pattern rejection and fatal budgets. The full draft passes 652 existing Node cases after one historical driver migrates its unchanged try{}catch(e){var e;} source across two inputs; focused Node/native coverage is 9287/9287 static with zero dynamic operations. The unchanged scoping-redeclaration-test.js produces the same 16 PASS lines and no FAIL lines on both hosts. Canonical integration and full corpus acceptance are pending.

Reviewed sources: [ECMAScript 2025 Annex B.3.4](https://262.ecma-international.org/16.0/#sec-variablestatements-in-catch-blocks), V8 [parser-base.h](https://github.com/v8/v8/blob/3278125d2ae7aa2e4e0c08173d87e62e0c6e18bd/src/parsing/parser-base.h) and [scopes.cc](https://github.com/v8/v8/blob/3278125d2ae7aa2e4e0c08173d87e62e0c6e18bd/src/ast/scopes.cc), pinned to 3278125d2ae7aa2e4e0c08173d87e62e0c6e18bd. V8 distinguishes simple catch names from destructuring and excludes catch scopes from var-conflict checks. The implementation preserves Rift's own planner and activation design.
